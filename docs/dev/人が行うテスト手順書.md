## 始める前に

### 注意

- **実際にマウスとキーボードが動く**。作業中のファイルは保存しておく。
- 見られて困るウィンドウは閉じておく。画像が見つからなかったときの画面は、`build\logs` にそのまま保存される。
- 実行中は、マウスやキーボードに触らない（スクリプトが「〜してください」と表示したときを除く）。
- **止めたいときは Alt+Shift+C を押す**。
- それでも止まらないときは、Ctrl+Alt+Del を押して「タスク マネージャー」を開き、`pikulix.exe` を選んで「タスクを終了する」を押す。Ctrl+Alt+Del は Windows が特別扱いするキーなので、Pikulix がどんな状態でも効く。

### 用意するもの

1. **ビルドと自動テスト**。リポジトリのフォルダで `rake test` を実行し、すべて通ることを確かめる。`build\pikulix.exe` ができる。テスト 4 で、自動テストが作る画像（`build\test\absent.png`）も使う。
2. **コマンドプロンプト**（Windows の昔からあるコマンド入力の画面。`cmd`）を、リポジトリのフォルダで開く。エクスプローラーでリポジトリのフォルダを開き、上のアドレスバーに `cmd` と入力して Enter を押すと、そのフォルダで開ける。
   - Windows 11 では、コマンドプロンプトは Windows Terminal（タブで複数の画面を開けるアプリ）の中で開く。
   - この手順書のコマンドは、コマンドプロンプト用である。PowerShell でも同じように実行できるが、終了コードの見方だけが違う（次項）。
3. **作業用のフォルダ**。次のコマンドで作る。`build` は git の管理外なので、ここに置いたスクリプトや切り取った画像が、誤ってコミットされることはない。

   ```
   mkdir build\manual
   ```

4. **画面の情報を控える**。「設定」→「システム」→「ディスプレイ」で、次を見ておく。結果を記録するときに使う。
   - ディスプレイの解像度（例: 1920 × 1080）
   - 拡大/縮小（表示倍率。例: 150%）
   - モニタが複数あるときは、どれがメイン ディスプレイか。Pikulix はメイン ディスプレイだけを探すので、操作する相手のウィンドウはメイン ディスプレイに置く。

### スクリプトの保存

テストに使う短いスクリプトを、この手順書から写して `build\manual` に保存する。文字コードは UTF-8 にする。Windows 11 のメモ帳と VS Code は、既定で UTF-8 で保存する。

メモ帳で保存するときは、「ファイルの種類」を「すべてのファイル」にする。「テキスト文書」のままだと `stop_sleep.rb.txt` のように `.txt` が付くことがあり、エクスプローラーは既定で拡張子を隠すので、見た目では気づきにくい。スクリプトが無いときは、`pikulix: スクリプトを読めません: ...` と表示され、終了コードは 2 になる。

### 終了コードの見方

exe を実行したあと、続けて次を実行すると、終了コードが表示される。

```
echo %ERRORLEVEL%
```

PowerShell では `$LASTEXITCODE` と入力する。

| 終了コード | 意味 |
| --- | --- |
| 0 | 成功 |
| 1 | スクリプトのエラー（画像が見つからなかった、など） |
| 2 | 起動できなかった |
| 3 | Alt+Shift+C で止めた |

### 表示倍率について

表示倍率が 100% でない画面で、画像の位置やクリックの位置がずれないこと（DPI 対応）も確かめたい。表示倍率が 100% の端末しかなければ、テスト 3 と 4 の間だけ一時的に 150% に変える（「設定」→「システム」→「ディスプレイ」→「拡大/縮小」）。サインアウトは要らない。終わったら戻す。

## テスト 1: 緊急停止

### 1-a. 待っている間に止める

`build\manual\stop_sleep.rb`:

```ruby
puts "60 秒待ちます。Alt+Shift+C で止めてください。"
sleep 60
puts "この行が表示されたら、止まっていない"
```

手順:

1. `chcp` を実行し、表示された番号を控える。`chcp` は、コンソールの文字コード（コードページ）を表示するコマンドである。日本語の Windows では、ふつう 932 である。
2. `build\pikulix.exe build\manual\stop_sleep.rb` を実行する。
3. メッセージが表示されたら、ブラウザなど別のウィンドウをクリックして前面にしてから、Alt+Shift+C を押す。
4. コンソールに戻り、`echo %ERRORLEVEL%` と `chcp` を実行する。

確かめること:

- [x] 押してすぐに止まり、`[pikulix] 緊急停止しました（Alt+Shift+C）` と表示される。
- [x] 別のウィンドウが前面にあっても効く。
- [x] 終了コードが 3 である。
- [x] `chcp` の番号が、手順 1 と同じである（65001 のままになっていない）。

このスクリプトはマウスもキーボードも使わないので、コンソールは最小化されない。

### 1-b. マウスを動かしている間に止める

`build\manual\stop_mouse.rb`:

```ruby
# マウスカーソルを、2 か所の間で動かし続ける。
loop do
  hover [200, 200]
  hover [600, 400]
end
```

手順:

1. `build\pikulix.exe build\manual\stop_mouse.rb` を実行する。
2. マウスカーソルが動き出したら、Alt+Shift+C を押す。
3. `echo %ERRORLEVEL%` を実行する。
4. メモ帳などを開き、`abc` と打ってみる。

確かめること:

- [x] マウスカーソルが動き出す前に、コンソールのウィンドウが最小化される。
- [x] Alt+Shift+C ですぐに止まり、コンソールのウィンドウが元に戻って前面に出る。
- [x] 終了コードが 3 である。
- [x] 止めたあと、Alt や Shift が押されたままになっていない（`abc` が大文字にならない。メニューが開かない）。

### 1-c. Ruby だけの無限ループを止める

`build\manual\stop_loop.rb`:

```ruby
puts "無限ループに入ります。Alt+Shift+C で止めてください。"

```

手順と確かめることは 1-a と同じである（別のウィンドウを前面にする必要はない）。

- [x] すぐに止まり、終了コードが 3 である。

3. もう一度 `build\pikulix.exe samples\notepad.rb` を実行する。
4. 終わったら、ペイント（スタートメニューで「ペイント」を検索）を開き、Ctrl+V を押す。

- [x] 手順 2 で切り取った画像が貼り付けられる。

終わったら、メモ帳とペイントを保存せずに閉じる。

## テスト 3: 画像を探してクリック（`samples\click_image.rb`）

### 準備

1. クリックしても困らないものを選ぶ。例えば、タスクバーのスタートボタン（クリックするとスタートメニューが開く）。
   - 管理者として動いているアプリ（一部のゲームのランチャー、タスク マネージャーなど）は、ここでは選ばない。画像は見つかり、カーソルも動くが、クリックが届かない（下の「管理者として動いているアプリを相手にする」で確かめる）。
2. マウスカーソルを対象から離しておく。マウスが乗っていると、色が変わった状態で切り取ってしまう。
3. Win+Shift+S を押す。Snipping Tool（Windows 標準の画面切り取りツール）が起動し、画面が暗くなる。上に出る切り替えで「四角形」を選び、対象を囲む。少しまわりを含めてよい。
4. 画面の右下に出る通知をクリックすると、Snipping Tool のウィンドウが開く。Ctrl+S を押し、リポジトリの `samples` フォルダに、`target.png` という名前で、ファイルの種類を PNG にして保存する。
   - 通知を見逃したときは、「ピクチャ」→「スクリーンショット」に自動で保存されていることがある（Snipping Tool の設定による）。それを `samples\target.png` にコピーする。
   - **`samples\target.png` はコミットしない**。テストが終わったら消す（最後の「後片付け」）。

### 実行

```
build\pikulix.exe samples\click_image.rb
echo %ERRORLEVEL%
```

### 確かめること

- [x] マウスカーソルが対象の中心へ動き、クリックされる（スタートボタンならスタートメニューが開く。Esc で閉じる）。
- [x] 次のようなログが出る（数値は環境によって違う）。

  ```
  [pikulix] exists "target.png": (24, 1032) で発見（一致度 0.998、31 ms）
  [pikulix] click "target.png": (24, 1032) で発見（一致度 0.998、28 ms）
  [pikulix] click (48, 1056)
  ```

- [x] 終了コードが 0 である。
- [x] ログの一致度と、探すのにかかった時間（ms）を記録する。テンプレートマッチングを自前実装のままでよいか（未決定事項）の判断材料になる。

### 表示倍率を変えて、もう一度

表示倍率が 100% でない状態でも行う。いまの端末が 100% なら、150% に変える。

1. 表示倍率を変える（「始める前に」の「表示倍率について」）。
2. 見た目の大きさが変わるので、準備の 3〜4 をやり直して `samples\target.png` を作り直す（上書きする）。
3. もう一度実行する。

- [x] クリックの位置が対象の中心からずれていない。

表示倍率は、テスト 4 が終わるまで、このままにしておく。

### 管理者として動いているアプリを相手にする

Windows は、権限の低いプログラムから、管理者として動いているアプリへの入力を捨てる（UIPI という保護の仕組み）。このとき、Pikulix が警告を出すことを確かめる。

1. タスク マネージャーを開く（Ctrl+Shift+Esc）。タスク マネージャーは、管理者として動く。
2. タスク マネージャーの中の、クリックしても困らないもの（左の「パフォーマンス」など）を切り取り、`samples\target.png` として保存する（上書きする）。
3. ふつうに開いたコマンドプロンプトから、もう一度実行する。

- [x] マウスカーソルは対象へ動くが、クリックは効かない（画面が切り替わらない）。
- [x] ログの最後に、次の警告が出る。終了コードは 0 である。

  ```
  [pikulix] click (412, 318)
  [pikulix] 警告: 操作の相手のウィンドウ「タスク マネージャー」は、管理者として動いているようです。このままでは、クリックやキー入力が届きません。Pikulix を管理者として実行してください
  ```

- 2026-11-17: 管理者として動くゲームのランチャーを対象にしたところ、画像は一致度 1.000 で見つかり（32 ms と 20 ms）、カーソルも動いたが、クリックが届かなかった。これをきっかけに、警告を追加した。
- 2026-11-17: タスク マネージャーを対象にして、警告が出ることを確かめた。Pikulix を管理者として実行したときにクリックが効くことは、確かめないことにした（作成者の判断。管理者として動くアプリを操作する予定がないため）。

## テスト 6: 日本語入力（IME）がオンのときの `type`

IME は、かな漢字変換をする日本語入力の仕組みである。半角/全角キーでオンとオフを切り替える。タスクバーの右端の表示が「あ」ならオン、「A」ならオフである。

これは合否を決めるテストではない。どうなるかを見て、記録する。結果によっては、`type` の前に IME をオフにする仕組みが要るかを検討する。

`build\manual\ime.rb`:

```ruby
puts "5 秒以内に、メモ帳の中をクリックしてください。"
sleep 5
type "type: abc あいう 123 !?\n"
paste "paste: abc あいう 123 !?\n"
key "a", "b", "c", "enter"
```

手順:

1. メモ帳を開き、半角/全角キーで IME をオンにする（「あ」になる）。
2. コマンドプロンプトで `build\pikulix.exe build\manual\ime.rb` を実行し、5 秒以内にメモ帳の中をクリックする。あとは触らない。
3. 結果を見る。
4. メモ帳の内容を消し、IME をオフ（「A」）にして、同じことをする。

記録すること（IME オンとオフのそれぞれ）:

- `type` の行が、書いたとおりに入ったか。未確定の文字（下線付き）になったり、別の文字に変わったりしなかったか。
- `paste` の行が、書いたとおりに入ったか。
- `key` の行（`a`、`b`、`c`、Enter）がどうなったか。IME オンでは「あbc」のように変換されることが考えられる。
- 終わったあと、IME の状態（「あ」か「A」か）が変わっていないか。

結果（2026-11-17）:

| | IME オン | IME オフ |
| --- | --- | --- |
| `type` の行 | 書いたとおり | 書いたとおり |
| `paste` の行 | 書いたとおり | 書いたとおり |
| `key` の行 | 「あｂｃ」（Enter は確定に使われたとみられる） | 「abc」と改行 |
| 終わったあとの IME | 変わらない | 変わらない |

終わったら、メモ帳を保存せずに閉じる。

### Pikulix を 2 つ同時に実行する

緊急停止のホットキーは、1 つのプログラムしか登録できない。登録できなかった Pikulix は、入力を送らずにエラーで終わる、という作りにしてある。

1. Windows Terminal でタブを 2 つ開き、どちらもリポジトリのフォルダへ移動する（`cd /d リポジトリのフォルダ`）。
2. タブ A で `build\pikulix.exe build\manual\stop_sleep.rb` を実行する。
3. 60 秒以内に、タブ B で `build\pikulix.exe build\manual\stop_mouse.rb` を実行し、`echo %ERRORLEVEL%` を実行する。
4. Alt+Shift+C を押す。

- [x] タブ B は、マウスを動かさずに、すぐにエラーで終わる。メッセージは「緊急停止のホットキー（Alt+Shift+C）を登録できなかったので、操作を中止しました。…」で、終了コードは 1 である。

### Ctrl+C で止める
